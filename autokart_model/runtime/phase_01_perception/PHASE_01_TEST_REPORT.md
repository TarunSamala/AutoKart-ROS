## Performance observations

On this x86_64 host, a zero-filled 640×480 image with the actual ONNX model was run 30 times after 5 warmups: median inference 21.06 ms, p95 24.38 ms, whole detector 26.46 wall FPS, process CPU 702.7% across cores, peak RSS 152.5 MB. A 100-frame labeled synthetic geometry loop ran at 799.31 wall FPS and 100.0% process CPU.

The 20-frame **real HP60C headless run**, `recordings/hp60c-bench-20261008-03`, used frames 4–20 for steady-state summaries: median RGB and depth frame rate 12.35 FPS each, output rate 12.43 FPS, inference 22.81 ms, processing 39.52 ms, valid-range depth pixels 62.55%, process CPU 385.26% across cores, and peak RSS 325.72 MB. First-frame inference took 110.11 ms after model startup. The old cumulative mailbox-overwrite count rose from 4 at the first recorded frame to 7 at frame 3, then remained at 7. This counts complete paired frames replaced before processing, not USB packet loss. All 20 recorded RGB and depth sequence IDs and timestamps matched, and the SDK registration flag was true. Intrinsics in the first recorded frame were fx 585.2704, fy 585.0195, cx 335.9750, cy 239.9636. These measurements reflect an indoor room scene without cones and do not establish detection accuracy, depth-scale accuracy, physical alignment, or Raspberry Pi throughput.

After the latest bridge rebuild, a live browser session recovered automatically when the HP60C reappeared on USB. Over a 10.152-second sample, the callback supplied 126 complete RGB/depth pairs, the pipeline processed 100, and the latest-frame mailbox overwrote 26 unread pairs: 12.41 acquisition FPS, 9.85 processing FPS, and 20.63% mailbox overwrite rate for that interval. The first and last status samples reported process CPU 581.75% and 623.01% across cores and peak RSS 225.95 MB and 230.20 MB; these are endpoint samples, not interval averages. The last sample reported 23.63 ms inference and 41.20 ms processing. No cones were visible in this measured interval. The SDK logged transient startup size warnings, a frame timeout, and `CALIBRATION_UNAVAILABLE` before calibrated live frames resumed.

The revised offline evaluator reran the actual 416×416 checkpoint on 20 original 640×480 HP60C RGB frames from `recordings/hp60c-bench-20261008-03`. A contact-sheet review found no visible cones in any of those frames; all 20 were explicitly labeled as cone-free in `recordings/hp60c-bench-20261008-03-negative-labels.json`. At confidence 0.25, 0.40, 0.54, and 0.70, each crossed with NMS IoU 0.45, 0.50, and 0.60, the model yielded zero false positives. Median inference was 21.40 ms and p95 was 23.26 ms on this x86_64 host. Because the set has no positive cones, recall, precision, AP50, and mAP50–95 are undefined, not 100%. The actual missed-cone rate seen in the user-described screenshot cannot be calculated without that frame and complete manual boxes.

The system `python -m pytest` without `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` failed before test collection because its installed `anyio` pytest plugin imports `_pytest.scope`, which is absent from the system pytest. This is an environment issue; the suite passes with plugin autoload disabled. Creating a venv on this host also failed because Debian's `python3-venv`/`ensurepip` component is absent; editable `--user --no-deps` installation passed with already installed dependencies.

## Remaining issues and verdict

The first live attempt failed to return calibrated frames because the SDK exposed intrinsics only after stream startup; the bridge was changed to retry calibration, after which live capture passed. The vendor SDK logged a transient `getMjpegSize` failure and startup timeout, then streamed normally. One observed USB disconnect/reconnect recovered to live capture; systematic reconnect endurance has not been tested. The operator-confirmed 180 mm level bench pose now resolves the missing-mount configuration in code, but the camera was absent during this upgrade. Physical RGB/depth alignment, depth-scale accuracy, surveyed ground-contact error, and positive-cone detection metrics remain unverified. No preprocessing defect was found; the cause of missed cones remains undetermined without raw labeled positive frames. The chosen model detects only orange traffic cones, so it cannot confirm colored boundary gates. **Phase status: TESTING. Verdict: PROTOTYPE TEST REQUIRED.**
