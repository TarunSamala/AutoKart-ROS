## Axis convention (inferred, not authoritative)

No metadata establishes the STL parts' native axis convention, so it was inferred from part geometry:

- `Axle 4.0.stl`'s longest dimension (214 mm) runs along native **X**, and it is the actual rear axle shaft → native X is **lateral** (left/right).
- The full non-Engine assembly's native **Z** extent (441.3 mm) is by far the largest, and matches the spread of axle-adjacent small parts (bearings, spacers) along Z → native Z is **longitudinal** (forward/rear).
- Native **Y** is the remaining, smallest extent (133.5 mm) → **vertical** (up).
- Output mapping: `(forward, left, up) = (native Z, native X, native Y)`. This is right-handed given a right-handed native frame (Z × X = Y, confirmed algebraically).

**This is inference, not ground truth** — if any individual part's STL was exported with its own inconsistent local origin/orientation (a real risk with per-component CAD exports), this mapping could be wrong for that part specifically. Not independently verified against the other parts beyond visual bounding-box plausibility.

## Scale factor and residuals

Uniform scale was calibrated on the **forward (length)** extent only, forcing it to exactly 2.400 m (the dimension sheet, both profiles). Width and height were **not** independently adjusted — per the task's explicit instruction ("apply ONE uniform scale factor... do not stretch axes independently") — so their residuals show how much this RC model's proportions actually differ from the real kart's:

| Dimension | Scaled (this STL) | Dimension sheet | Residual |
|---|---|---|---|
| Length (forward) | 2.400 m | 2.400 m | 0.000 m (calibrated on this) |
| Width (left/right) | 2.358 m | 1.181 m | **+1.177 m** (≈2.0x too wide) |
| Height (up) | 0.726 m | 1.118 m | **−0.392 m** (≈35% too short) |

**Scale factor: 5.438** (model units, assumed mm, to real-world metres) — notably close to "1:5 scale," independently corroborating this STL's own stated scale and the RECON finding that it's an unrelated 1:5 RC model, not a scaled rendering of the real kart.

**Do not use this model's width/height for anything beyond a loose visual silhouette.** It is uniformly scaled by length only, as instructed, and its real proportions are simply different from the real kart's.

## Rear axle reference and alignment

Origin was placed at the bounding-box centre of `Axle 4.0.stl` (the actual rear axle shaft part) before scaling, then the whole assembly was translated so that point becomes world origin, in the output's `(forward, left, up)` frame — satisfying "align to rear axle centre, x forward, z up."

## Front wheels: proxy cylinders (no separable wheel mesh exists)

Every file in the `Steering` group was inspected by name; none is a wheel or tyre mesh — only hub, axle, mount, and fastener hardware (`frontwheelhub`, `front-axle-v5_1`, `Steering_Mount`, `wheel-lock-nut`, etc.). Per the task's own stated fallback, proxy cylinders were synthesized instead: one left/right pair **per kart profile** (`front_wheel_{shared,built}_{left,right}.glb`), since the two profiles' front tracks differ.

These proxy wheels are positioned at each profile's actual `wheelbase_m` (forward) and `front_track_m/2` (lateral) — real measured geometry — but their radius/width is the same ASSUMED tyre figure used throughout the rest of this branch, not a measurement. A viewer rotating these by the live steering angle is a Step 7 (D3) task, not this script's.
